# Usage

You do not call the tools yourself. Ask the model for a task that needs several MCP calls. The model then finds the
tools with `search_tools` and writes one program for `run_code`.

Ask, for example:

```text
Find my open Jira issues that have no update in the last 14 days, and give me their keys and titles.
```

Without code-mode, the model calls the Jira tools one by one, and each result goes into the context. With
code-mode, the model writes one program. The program does the loop and the filter, and only the final list goes
into the context.

## The tools

| Tool | What it does |
| --- | --- |
| `mcp__code-mode__search_tools` | Finds MCP tools by keywords. For each tool, it gives the name, one line of description and, when known, the argument types and the [result shape](#result-shapes). It also gives the [hints](./hints.mdx) for the servers that it finds. An empty query lists all MCP tools. |
| `mcp__code-mode__run_code` | Runs one program in the [sandbox](./how-it-works.mdx#sandbox) and gives back its return value. |
| `mcp__code-mode__add_hint` | Proposes a hint for a server. The proposal has no effect until you approve it. See [Hints](./hints.mdx). |
| `mcp__code-mode__remove_hint` | Hides a wrong hint in the current session and proposes to remove it from its hint file. See [Remove a hint that is wrong](./hints.mdx#remove-a-hint-that-is-wrong). |

`search_tools` and `run_code` load in every session. `add_hint` and `remove_hint` load only when the model needs them.

## Programs

A program is the body of an async JavaScript function. In the program:

- `await call("mcp__<server>__<tool>", args)` calls an MCP tool and gives its result.
- `await tools["<server>"]["<tool>"](args)` is the same call in a different form.
- `await sleep(ms)` waits for the given number of milliseconds. Use it to poll a slow job.
- `console.log(...)` adds a line to the console output.
- `return value` sets the result. The model gets the value as JSON.

An example program:

```js
const [resources, user] = await Promise.all([
  call("mcp__claude_ai_Jira__getAccessibleAtlassianResources", {}),
  call("mcp__claude_ai_Jira__atlassianUserInfo", {}),
])
return { resourceCount: resources.length, hasAccountId: Boolean(user.account_id) }
```

A program that polls a job until it is done:

```js
let job = await call("mcp__ci__start_build", { branch: "main" })
while (job.status === "running") {
  await sleep(5000)
  job = await call("mcp__ci__get_build", { id: job.id })
}
return { status: job.status, url: job.url }
```

The `timeoutSeconds` limit of the run includes the time in `sleep`. See [Configuration](./configuration.mdx).

At most 8 nested calls of one run wait for a reply at the same time. If a program starts more, for example with
`Promise.all` over 300 ids, the other calls wait in a queue. Thus a program does not send all its calls to a server
at once.

What a call gives:

- If the tool gives structured content, the call gives that object.
- If the tool gives text that is JSON, the call gives the parsed value.
- Else the call gives the text.
- If the call fails or a permission rule denies it, the call throws an `Error`. The program can catch it.

A large result works the same way. If a tool result is too large for the context, Claude Code saves it to a file.
The model then gets only a note with the path. In a program, the plugin reads that file and the call gives the full
result. The plugin reads only files in the `tool-results` folder of the current session, up to 4 MiB. If the file
is larger, or Claude Code saved only part of the result, the call throws an `Error`. Then ask the tool for less
data, for example one page or fewer fields.

A program can call only MCP tools. It cannot call built-in tools such as `Bash` or `Read`, or the code-mode tools.
It has no `require`, `fetch`, `process`, `setTimeout` or file system.

## The result

The model gets one text with these parts:

1. The return value as formatted JSON, at most 20,000 characters. A longer value is cut, with a note that tells
   the model to return less data.
2. The console lines, if there are any, at most 4,000 characters.
3. One line for each MCP call that the program made, with its size and its shape. See
   [Output projection](#output-projection).
4. A request to propose a hint, if the run works after earlier tries failed. See
   [Hints](./hints.mdx#approve-hints-that-the-model-proposes).
5. The hints for the servers whose calls failed, if there are any.

If the program throws, the first part is the error and the lines of the program where it occurred.

## Output projection

Output projection is on by default. To turn it off, set the option `projection` to `false`.

The program is the filter: the model writes it for the task, so it keeps the exact values. A filter can miss the
data that the model needs, because the model wrote it before it saw the data. Output projection lets the model
see what it removed, and fix the filter without a new MCP call.

The last part of the result has one line for each MCP call:

```text
--- 2 MCP calls: 184k characters in, 2k out ---
#4 mcp__slack__search 181k {messages: [312 × {ts, text, user, …+5}], next_cursor}
#5 mcp__slack__user failed
await recall(n) returns result #n again, with no new call.
```

1. `#4` is the number of the result in the session.
2. `181k` is the size of the result, in characters of JSON.
3. The shape shows the keys and the array lengths, not the values.

The shape shows the keys of an object only if they are field names, such as `status` or `next_cursor`. If the keys
are data, for example emails, ids or the names of services, the shape shows only the number of keys. Then the data
stays out of the context, as the program intended.

The plugin keeps the newest 50 results of the session in memory, up to 8 million characters. A larger result is not
kept. The results stay until the session ends. A later program can read one again with `await recall(4)`. Then the
line says how old the result is, for example `recalled: #4 (12 min old)`. If the data changes often, the model must
call the tool again.

A call to `recall` makes no MCP call and no permission check, because the call that made the result was approved.
This is also true with `approval` set to `per-call`. A failed call is not kept. If the plugin cannot read the session
id, it keeps the results only until the run ends.

The line also tells the model these facts:

- A call is the same as an earlier call, with the same tool and arguments.
- The program returned nothing, but its calls returned data.
- The return value was cut. Then the plugin keeps the whole value, and the note gives its number for `recall`.

To measure the experiment, set the option `metrics` to `true`. The plugin then writes one line for each run to
`~/.claude/code-mode/metrics/<session id>.jsonl`. A line has sizes and counts only: no data, no arguments and no
program. To compare sessions with `projection` on and off, run this command:

```bash
node scripts/projection-report.mjs
```

## Result shapes

When a nested call works, the plugin saves the shape of its result for that MCP tool. `search_tools` then shows the
shape under the argument types, also in later sessions:

```text
### mcp__slack__search
Search messages
args: { query: string; count?: number }
returns (earlier call): {messages: [{ts, text, user, …+5}], next_cursor}
```

Thus the first program of a session can use the correct fields. Without a shape, the model must guess the fields,
and a wrong guess costs one more run.

- The shape has the same rules as the shape in the [output projection](#output-projection) lines. It shows field
  names, not values. It has no array lengths.
- A result that is text has the shape `text`.
- An empty result does not change a known shape.
- The plugin keeps the newest 500 shapes in `~/.claude/code-mode/shapes.json`. It loads only the shapes that have
  field names and punctuation. It ignores all other text in the file.
- A server can change the shape of its results. Then the program fails one time, and the next call saves the new
  shape.

Result shapes are part of output projection. If the option `projection` is `false`, the plugin does not save or show
shapes.

## Make the model use code-mode

When a session starts, the plugin tells the model to use `run_code` for MCP calls. The plugin tells it again after
`/clear` and after a compaction. The model calls an MCP tool directly only when `run_code` fails with an error that
a changed program cannot fix.

To stop all direct MCP calls, turn on the option `blockDirectMcp`. Then a direct MCP call gets a denial that tells
the model to use `run_code`. See [Configuration](./configuration.mdx).
