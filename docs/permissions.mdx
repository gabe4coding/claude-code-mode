# Permissions

Your permission rules apply to each MCP call in a program, as they apply to a direct call.

## In short

- **Manual mode:** approve the `run_code` call. You see the full program in the prompt. With the default
  `approval: program`, this approval also covers the nested calls that no rule decides.
- **Auto mode:** add an allow rule for each MCP tool that your programs use. Without an allow rule, auto mode
  denies a nested call. See [Auto mode needs allow rules](#auto-mode-needs-allow-rules).
- **Headless (`claude -p`):** add an allow rule for each MCP tool that your programs use. Without one, the nested
  call is refused. See [Headless sessions need allow rules](#headless-sessions-need-allow-rules).
- **Deny rules** always apply. A deny rule takes the tool out of the session, so no program can call it. See
  [Deny rules](#deny-rules).
- **Files:** `readFile` reads only the files that Claude Code reads with no prompt, and the files from `saveFile`.
  See [Files](./usage.mdx#files).
- **MCP resources:** `resources` and `readResource` get the normal check of `ListMcpResourcesTool` and
  `ReadMcpResourceTool`, also with `approval: program`. In auto mode, add allow rules for these two tools.
- **Saved functions:** their MCP calls are nested calls, with the same checks. See
  [Saved functions](./functions.mdx).

## The check of a nested call

Claude Code checks the `run_code` call as any other tool call. Then the plugin checks each nested call against your
rules:

| Result of the check | What the plugin does |
| --- | --- |
| A deny rule matches | Denies the call. The program gets an error. |
| An allow rule matches | Does the call as a direct call. |
| No rule, `approval: program` | Does the call. Your approval of the program covers it. |
| No rule, `approval: per-call` | Does the call as a direct call, so Claude Code asks you. |
| Your organization sets a limit | Does the call as a direct call, so Claude Code asks you. |

## Results by permission mode

| Mode | Nested call with an allow rule | Nested call with no rule |
| --- | --- | --- |
| Manual (default) | Runs. | `program`: runs, covered by your approval of `run_code`. `per-call`: you get a prompt for each call. |
| Auto | Runs. | Denied. |
| Headless (`claude -p`) | Runs. | Refused. Nobody can approve it. |

## Headless sessions need allow rules

In `claude -p`, nobody can answer a permission prompt. Thus Claude Code refuses a nested call that no rule allows,
also with `approval: program`. The program gets this error:

```
code-mode: $.mcp.call(<server>, <tool>) refused: Claude requested permissions to use mcp__<server>__<tool>, but you haven't granted it yet.
```

Add an allow rule for each MCP tool that your programs use. For one run, use `--allowedTools`:

```bash
claude -p "…" --allowedTools "mcp__code-mode__run_code,mcp__code-mode__search_tools,mcp__claude_ai_Jira__getJiraIssue"
```

## Deny rules

A deny rule for an MCP tool or a server takes the tool out of the session. Thus `search_tools` does not show it, and
no program can call it:

- If the program names the tool in a literal call, the [check before a run](./usage.mdx#the-check-before-a-run)
  stops the program. No call occurs. If the server of the tool is connected, the result says that a deny rule can
  hide the tool.
- If the program gets the tool name from a variable, the call throws an error in the program.

Claude Code does not tell the plugin which rule hides a tool. Thus the result cannot say if the name is wrong or if
a deny rule hides the tool.

## Auto mode needs allow rules

In auto mode, Claude Code sends each MCP call that a plugin starts to the classifier. The classifier judges only
actions that the model asked for. Thus it gives no verdict for a nested call, and Claude Code denies the call:

```
The server-side auto mode classifier gave no verdict for mcp__…: the request that produced this action did not ask for one.
```

The option `approval` cannot change this. It is a limit of Claude Code, and the plugin does not try to go around it.

Add an allow rule for each MCP tool that you use from `run_code`, in `~/.claude/settings.json`:

```json
{ "permissions": { "allow": ["mcp__claude_ai_Jira__getJiraIssue", "mcp__claude_ai_Jira__searchJiraIssuesUsingJql"] } }
```

- Allow single read-only tools when you can. A rule for a full server (`"mcp__claude_ai_Jira"`) also allows its
  write tools, for example create, update and delete.
- An allow rule applies to every call of the tool: direct calls from the model and calls in other sessions too.
- Add each name of a server. In the desktop app, a claude.ai connector can have a UUID name
  (`mcp__fcef2cd1-…__getJiraIssue`). In terminal and headless sessions it has a `claude_ai_` name
  (`mcp__claude_ai_Jira__getJiraIssue`). A rule matches only the name that it contains.
- To get the exact name of a tool in the current session, run `search_tools`.

| Issue | What it reports |

| [anthropics/claude-code#100575](https://github.com/anthropics/claude-code/issues/100575) | Auto mode refuses the `$.tool.call` of a plugin with "no verdict", unless an allow rule matches (Claude Code 2.1.294). It proposes three fixes. |
| [anthropics/claude-code#99214](https://github.com/anthropics/claude-code/issues/99214) | Auto mode refuses the `$.mcp.call` of a plugin with the same error (Claude Code 2.1.286). The reporter says that a project allow rule did not help. |

The plugin uses `$.tool.call` for a nested call with an allow rule, so the allow rule works. It uses `$.mcp.call`
for a nested call with no rule and `approval: program`. When Claude Code fixes one of these issues, test the plugin
again in auto mode without allow rules.
